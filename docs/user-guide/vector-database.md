# Vector Database

The engine stores document embeddings in a **LanceDB** vector database for semantic search and retrieval. This is the final output of the pipeline and is what downstream tools (chat interfaces, analysis tools) query against.

## Table schema

Each row in the LanceDB table (`all_document_types` by default) represents a single document — this could be a report section, a safety issue, a recommendation, a summary, or the full report text. Every row has a vector embedding of the `document` text plus the following metadata columns:

| Column | Type | Description |
|---|---|---|
| `document` | `str` | The actual text content (embedded into the `vector` column). This is what gets semantically searched. |
| `vector` | `Vector(1536)` | The embedding vector generated by Azure OpenAI's `embed-v-4-0` model. |
| `document_id` | `str` | Unique identifier for this document, e.g. `TAIC_m_2024_001_sec_2.1`. |
| `report_id` | `str` | The report this document belongs to, e.g. `TAIC_m_2024_001`. |
| `document_type` | `str` | One of `section`, `summary`, `report_text`, `recommendation`, `safety_issue`. |
| `year` | `int` | Investigation year extracted from the report ID. |
| `mode` | `str` | Transport mode: `a` (air), `r` (rail), `m` (marine). |
| `agency` | `str` | Investigation agency name (e.g. `TAIC`, `ATSB`, `TSB`). |
| `agency_id` | `str` | Agency's own report identifier. |
| `url` | `str | None` | URL to the original report on the agency's website. |
| `location` | `str | None` | Standardized occurrence location (4-part: exact location, city, region, country). |
| `occurrence_date` | `datetime | None` | Local occurrence date extracted from the report. |
| `occurrence_type` | `str | None` | Type of occurrence (varies by mode, e.g. `collision`, `derailment`, `ditching`). |
| `fatalities` | `int | None` | Number of fatalities from the occurrence. |
| `injuries` | `int | None` | Number of non-fatal injuries. |
| `publication_date` | `str | None` | Date the report was published by the agency. |
| `metadata_json` | `str | None` | Full metadata dict serialised as JSON. Contains all extracted occurrence and vehicle details (aircraft, trains, vessels, pilots, etc.) — see [ExtractionModels](../api/extractionmodels.md) for the full structure. |

## Connecting

```python
import lancedb

db = lancedb.connect("path/to/vector_db")
table = db.open_table("all_document_types")
```

The database URI is configured via the `VECTORDB_URI` environment variable.

If you are using a Azure hosted LanceDB instance, you can connect with a link of the format 'az://<container_name><path_to_db>' and in your `.env` file have 'AZURE_STORAGE_ACCOUNT_NAME' and 'AZURE_STORAGE_ACCOUNT_KEY' set to your Azure storage account credentials.

## Querying

The `search()` method accepts a `query_type` parameter to control how the query is executed:

| `query_type` | Behaviour |
|---|---|
| `"vector"` | Semantic search using the embedding model (default) |
| `"fts"` | Keyword full-text search on the `document` column |
| `None` | Filter-only — no ranking, returns all matching rows |

### Vector (semantic) search

Find documents semantically similar to a query:

```python
table.search("engine failure on takeoff", query_type="vector").limit(10).to_pandas()
```

By default, the search uses cosine distance. The `_distance` column ranges from 0 (identical) to 2 (opposite). Convert to a relevance score with `1 - _distance`:

```python
results = table.search("engine failure", query_type="vector").limit(10).to_pandas()
results["_distance"] = 1 - results["_distance"]
```

### Vector search with filters

Apply structured filters alongside a vector search. Use `prefilter=True` to apply the filter before the vector search for better performance:

```python
table.search("engine failure", query_type="vector")
    .where("mode = 'a' AND year >= 2020", prefilter=True)
    .limit(10)
    .to_pandas()
```

```python
table.search("derailment", query_type="vector")
    .where("fatalities > 0")
    .limit(20)
    .to_pandas()
```

### Full-text search (FTS)

The `document` column has a full-text search index. For keyword matching, use `query_type="fts"`:

```python
table.search("propeller strike", query_type="fts").limit(10).to_pandas()
```

FTS returns a `_score` column representing the keyword relevance. Combined with filters:

```python
table.search("engine fire", query_type="fts")
    .where("year >= 2020")
    .limit(20)
    .to_pandas()
```

### Filter-only (no vector search)

Retrieve rows by metadata without ranking by passing `None` as the query:

```python
table.search(None)
    .where("agency = 'ATSB' AND document_type = 'safety_issue'")
    .limit(50)
    .to_pandas()
```

### Text matching on `metadata_json`

The `metadata_json` column is a plain JSON string. You can filter on it using SQL string functions in the `where` clause:

```python
# Find all documents involving a helicopter
table.search(None)
    .where("metadata_json LIKE '%Helicopter%'")
    .limit(20)
    .to_pandas()
```

```python
# Find documents where a specific vessel name is mentioned
table.search(None)
    .where("metadata_json LIKE '%Spirit of Auckland%'")
    .limit(20)
    .to_pandas()
```

More precise filtering can be done by reading the LanceDB table into DuckDB or Pandas:

```python
# Load into pandas for more complex JSON parsing
df = table.search(None).limit(10_000).to_pandas()
helicopter_df = df[df["metadata_json"].str.contains("Helicopter", na=False)]
```

!!! note

    The `metadata_json` field is a verbatim JSON copy of the raw metadata dict extracted by the AI. Different report modes (air/rail/marine) have different fields in this dict. String matching with `LIKE` is a simple way to search across all modes without needing to know the exact schema. See the [metadata extraction models](../api/extractionmodels.md) for the full structure of what the JSON contains per mode.

### Combining everything

```python
results = (
    table.search("loss of control in-flight")
    .where("mode = 'a' AND year >= 2015 AND metadata_json LIKE '%Cessna%'")
    .limit(10)
    .to_pandas()
)
```

## Available columns for filtering

The `where()` clause supports all columns in the schema above. The most commonly used filters are:

- `mode` — restrict to a transport mode (`'a'`, `'r'`, `'m'`)
- `year` — filter by investigation year (`>=`, `<`, `=` etc.)
- `agency` — restrict to a specific agency
- `document_type` — filter by document type
- `fatalities`, `injuries` — numeric range filters
- `location` — text match on standardized location
- `occurrence_date` — date range filters
- `metadata_json` — text matching via `LIKE` as described above
